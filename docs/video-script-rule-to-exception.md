# سناریوی ویدیوی واقعی مرکز کنترل عملیات

هدف: نمایش چرخه `Rule → Exception → Action → KPI` در ۹۰ ثانیه، بدون استفاده از داده ساختگی یا افشای اطلاعات مشتری.

## پیش‌نیاز ضبط

- یک Tenant نمایشی مجزا از محیط عملیاتی اصلی انتخاب شود.
- یک پرونده نمونه بدون نام، شماره تماس، مبلغ محرمانه یا شناسه مشتری آماده شود.
- یک Rule کم‌ریسک برای همان پرونده فعال و سپس داده ورودی کنترل‌شده برای Trigger آن ثبت شود.
- نمایش اعلان‌های سیستم‌عامل، تب‌های دیگر و اطلاعات هویتی کاربر در ضبط خاموش باشد.

## Shot list و نریشن

| زمان | تصویر واقعی | نریشن پیشنهادی |
|---|---|---|
| ۰۰–۰۷ | نمای کلی مرکز کنترل | «مرکز کنترل سپند، وضعیت عملیات را فقط گزارش نمی‌کند؛ هر انحراف را به اقدام مسئول‌دار تبدیل می‌کند.» |
| ۰۷–۲۰ | تب Rule Builder و چهار Template | «کنترل از یک Rule قابل توضیح شروع می‌شود: شرط، آستانه، شدت، مسئول، موعد و مسیر Escalation.» |
| ۲۰–۳۵ | ساخت Rule سفارشی | «در این مثال، نزدیک‌شدن ETA و ناقص‌بودن سند اجباری، شرط ایجاد Exception است.» |
| ۳۵–۴۸ | ثبت داده نمونه و Trigger | «با ورود داده منطبق، Rule اجرا می‌شود و یک Exception یکتا روی همان پرونده می‌سازد.» |
| ۴۸–۶۲ | Exception Workbench | «صف رسیدگی، منشأ، شدت، مالک و Due را کنار هم نشان می‌دهد؛ Acknowledge به معنی رفع نیست.» |
| ۶۲–۷۶ | ثبت اقدام و بستن Exception | «کارشناس اقدام و نتیجه را ثبت می‌کند و سابقه تصمیم برای ممیزی باقی می‌ماند.» |
| ۷۶–۹۰ | داشبورد و KPI | «زمان تشخیص تا اقدام، بستن در SLA و علت‌های تکراری، ورودی بهبود Rule بعدی هستند.» |

## قاعده انتشار

نسخه فعلی استقرار بررسی‌شده Rule فعال و Exception باز نداشت. بنابراین ضبط چرخه کامل فقط پس از آماده‌سازی Tenant نمایشی و ایجاد رویداد کنترل‌شده انجام شود؛ تصویر خالی نباید با داده نمایشی مونتاژ و به‌عنوان اجرای واقعی معرفی شود.
